# “Count Down” 美术与战斗特效设计

日期：2026-07-26

状态：视觉方向已由用户确认，等待书面规格复核

## 1. 目标

让玩家进入游戏后第一眼看懂“剩余时间就是生命与资源”，并用统一的暗金发条炼金术风格替换当前运行时代码生成的方块、圆形和纯色底板。

这次美术改造必须同时服务三件事：

1. 突出 GMTK 2026 主题 “Count Down”；
2. 提高棋盘模块、怪物类型和战斗状态的辨识度；
3. 保留当前玩法、数值、布局和无资源时的运行时回退能力。

## 2. 已确认的视觉方向

整体采用“暗金发条炼金术”：

- 世界观：沙粒是时间燃料，玩家的工坊把时间炼成能量球；来袭的“噬时机偶”试图偷走沙漏中的时间。
- 主色：暗紫黑与炭黑作为背景，黄铜与沙金作为时间装置主色。
- 功能色：火焰橙红、寒冷冰蓝、黑洞紫、携沙青白，延续现有类型颜色。
- 材质语言：黄铜边框、暗钢机壳、玻璃沙仓、齿轮、钟面刻度和发光裂缝。
- 图形语言：模块底座共享形状，功能由轮廓、炮口、管道方向和中心符号区分。
- 不把文字烘焙进图片；名称、数值和提示继续由 Unity 文本绘制。

确认调色板：

| 用途 | 色值 |
|---|---|
| 深背景 | `#0B0910` |
| 暗紫面板 | `#211826` |
| 黄铜 | `#B58248` |
| 沙金高光 | `#FFD676` |
| 危险红 | `#FF554D` |
| 冰蓝 | `#72DFF1` |
| 携沙青白 | `#80EAD6` |
| 黑洞紫 | `#A05CC4` |

## 3. 倒计时核心

### 3.1 巨型时间刻度环

采用已确认的第三种倒计时方案：巨大的时间刻度环跨越棋盘和战斗区域，作为世界空间的低亮度背景层。

- 圆环由 60 个独立刻度组成，显示剩余沙量占开局沙量的比例。
- 显示比例钳制在 `[0, 1]`；回沙超过开局值时圆环保持全亮，并用一次沙金外扩脉冲表达溢出，不增加第二圈。
- 基础环常驻，亮起的刻度从 12 点方向开始顺时针递减。
- 圆环位于战斗背景与棋盘内容之后，不接收射线或鼠标事件。
- 普通状态保持低亮度，避免遮挡炮弹、怪物、格子和模块。
- 剩余时间低于 20 秒时，亮起刻度从沙金渐变为危险红，圆环和数字进行缓慢脉冲。
- 扣沙时，缺失刻度产生一次向外熄灭波；回沙时，新亮刻度产生一次向内点亮波。
- 圆环使用独立的刻度渲染，而不是依赖自定义着色器；正式环纹素材缺失时仍可用程序化刻度运行。

### 3.2 数字与沙漏

- 保留 `mm:ss.mmm` 精确读数，并把它放在视觉中心附近的高对比小底板上。
- 读数始终绘制在战斗信息之上，不被世界空间对象遮挡。
- 保留实体沙漏作为“时间库存”的直观表现；沙漏内的沙量随剩余比例变化。
- 沙漏、数字和时间环共享警告阈值与颜色，不各自维护独立规则。

### 3.3 布局约束

- 保留当前“上方战斗区、左下棋盘、右下手牌/商店”的 60/40 布局。
- 时间环不能改变棋盘碰撞范围、怪物路径或发射器入口坐标。
- 1920×1080 与 1280×720 下，数字不得与波次、金币、手牌或准备阶段面板重叠。

## 4. 棋盘、战斗区域与发射器

### 4.1 棋盘

- 棋盘使用暗钢格面和细黄铜边框。
- 相邻格仍保留轻微明暗交替，但对比低于模块图标。
- 可放置、不可放置、悬停、诅咒和附魔继续使用颜色反馈，并增加细线刻纹，避免只靠颜色区分。
- 棋盘外框加入钟表机械结构，但不使用高频齿轮纹覆盖格子。

### 4.2 战斗区域

- 战斗背景是暗色机械输送通道，远处可见低对比钟盘、断裂刻度和沙尘。
- 背景中央允许时间环透出，边缘逐渐变暗。
- 战斗底板中央使用半透明或镂空渐变，棋盘实体格面遮住其下方的圆环部分，形成真正的前后层次。
- 背景细节不能与敌人轮廓同亮度，也不能制造假的炮弹或状态粒子。

### 4.3 沙炉发射器

- 原发射器重绘为“沙炉”：玻璃沙仓连接黄铜炉体，填充进度对应现有 `BufferFill01`。
- 充能时炉心由冷蓝逐渐转为沙金；满载射出时出现短促活塞运动和沙粒喷口。
- 发射口方向必须比装饰结构更明显，确保玩家看懂能量球从左向右进入棋盘。

## 5. 模块皮肤系统

项目共有 17 种模块。采用“全覆盖基础皮肤 + 核心模块精修”的范围。

### 5.1 共享规则

- 所有模块使用相同尺寸的黄铜/暗钢底座，以保证放入格子后的视觉重量一致。
- 攻击类：立体炮座和明确炮口。
- 路径类：扁平管道、入口/出口和发光方向标记。
- 辅助与附魔类：齿轮、坩埚、线圈或符文印章；不能看起来像会主动开火的炮塔。
- 模块等级继续由现有 UI 文本显示；皮肤不为每一级制作独立图片。
- 模块旋转只旋转需要表达方向的部分；附魔种子和固定地块逻辑不受皮肤旋转影响。

### 5.2 精修对象

下列 8 个对象拥有完整棋盘皮肤：

1. 沙炉发射器：玻璃沙仓、炉心和活塞喷口；
2. 收束器：90° 黄铜弯管和清楚的双向流光；
3. 查理激光塔：细长聚焦镜和红色准星核心；
4. 大卫炸弹塔：短粗臼炮、橙色压力仓；
5. 雪花发射塔：冰晶叉状炮口、冰蓝冷凝管；
6. 黑洞发射器：悬浮紫色引力环、暗色中心；
7. 火花发射塔：双极线圈、橙金电弧；
8. 热浪塔：环形散热片、红色脉冲炉心。

### 5.3 其余模块基础皮肤

| 模块 | 核心符号 |
|---|---|
| 比特币采矿机 | 齿轮钻头与金币压印 |
| 火焰增幅 | 双层火焰坩埚 |
| 分裂器 | T 形三通管 |
| 传送门 | 成对紫色时环 |
| 中续器 | 沙漏加号与续航线圈 |
| 加速器 | 双箭头和增压叶轮 |
| 核聚变 | 五点向中心汇聚 |
| 核裂变 | 中心向五点散开 |
| 火附魔 | 火焰烙印章 |
| 惊喜 | 多色棱镜问号核心，但不把文字烘焙进贴图 |

`GameSkin` 需要能按 `ModuleType` 返回棋盘皮肤和 UI 图标。任何字段缺失时继续回退到 `PrototypeSprites`，不能阻止游戏启动。

## 6. 敌人家族：噬时机偶

敌人的共同特征是暗钢机壳、钟面核心和倒转的指针。敌人到达终点代表它从玩家沙漏中偷走时间。

| 类型 | 造型 | 现有颜色与数值含义 |
|---|---|---|
| Swarm | “跳秒虫”：小型发条跳蚤，秒针快速摆动 | 黄色、最快、最低血量 |
| Normal | “窃时者”：标准钟表机偶，红色裂纹核心 | 红色、标准速度与血量 |
| Tank | “滞时铠”：厚重蓝钢钟壳，拖着摆锤 | 蓝色、慢、高血量 |
| Boss | “末日钟”：行走的破钟楼，橙色熔炉心脏 | 橙色、巨大、第 25 波 |

`Elite` 当前不在实际刷怪队列中，不单独制作正式皮肤；如果未来出现，先使用 Tank 皮肤配稀有度描边回退。

携沙是覆盖层而不是新怪物：

- 身体插有青白发光沙漏碎片；
- 少量青白沙粒逆时针绕行；
- 击杀后碎片和沙粒飞向沙漏/时间环；
- 不改变敌人主体皮肤，避免把携沙误认成第五种基础敌人。

## 7. 战斗特效

### 7.1 状态特效

- 灼烧：机壳裂缝发橙光，少量余烬绕行；每次伤害跳动时核心短促膨胀。
- 寒冷：外壳边缘结霜，身后出现缓慢旋转的秒针虚影，表达“时间走慢”。
- 融化：冰蓝碎片和橙色蒸汽同时向外爆开，中央出现约一帧的白金闪光；总时长约 0.35 秒。
- 携沙：青白沙粒和沙漏碎片常驻；死亡后触发回填飞行动画。

灼烧和寒冷同时存在时，两种常驻特效都降低亮度；触发融化后立即停止两种常驻特效，与现有状态清除逻辑一致。

### 7.2 即时反馈

- 普通受击：约 0.08 秒白闪和极短的刻度射线。
- 重击或爆炸：在普通受击基础上增加轻微缩放和较宽的冲击环。
- 死亡：钟面核心熄灭，机壳缩塌，飞出少量齿轮、刻度和断裂指针；普通怪总时长不超过约 0.3 秒。
- Boss 死亡可以延长并分阶段，但不能阻塞胜利逻辑。

### 7.3 画面与性能规则

- 常驻状态使用低亮度、贴轮廓的少量循环粒子。
- 融化、携沙死亡和低时间警报可以短暂高亮。
- 特效对象使用对象池或严格生命周期，限制同屏粒子数量。
- 不为普通伤害新增满屏跳字；保留关键组合提示。
- 特效不得改变命中判定、索敌、伤害时间点或敌人销毁语义。

## 8. 资产与代码边界

### 8.1 美术资产

生产资产放入：

`Assets/Art/Generated/Countdown/`

按用途分为：

- `Environment/`：时间环装饰、战斗背景、棋盘格面和外框；
- `UI/`：沙漏、面板与时间数字底板；
- `Modules/`：17 种图标和 8 个精修棋盘皮肤；
- `Enemies/`：4 种敌人主体与携沙覆盖层；
- `VFX/`：余烬、火焰片、冰晶、蒸汽、沙粒、刻度、齿轮碎片与柔光。

生成图片采用无文字、正交或近正交 2D 游戏精灵构图。需要透明背景的素材先在纯色键控背景上生成，再在本地去背并检查边缘。源图保留高分辨率版本，Unity 使用经过缩放和裁切的 PNG。

### 8.2 配置

扩展 `GameSkin`，集中保存：

- 环境与 UI Sprite；
- 按 `ModuleType` 映射的模块主体和图标；
- 按 `EnemyGoldType` 映射的敌人主体；
- 状态与一次性 VFX Sprite。

配置层只负责资源解析和回退，不处理战斗状态。

### 8.3 运行时视图

新增或拆分为职责明确的视图组件：

- `CountdownRingView`：读取 `SandClock`，更新亮起刻度、警告状态和扣沙/回沙反馈；
- `EnemyVisualController`：选择敌人主体，控制灼烧、寒冷、携沙、受击和死亡视觉；
- `CombatVfxService`：生成短生命周期的一次性特效并限制数量；
- 模块类继续维护自己的功能动画，但统一从 `GameSkin` 取得皮肤。

数据流：

- `SandClock` → `CountdownRingView`
- `Enemy` 状态变化 → `EnemyVisualController`
- `CombatDamage` 融化事件 → `CombatVfxService`
- `ModuleType` → `GameSkin` → 模块主体与 UI 图标

## 9. 回退与错误处理

- 缺失正式 Sprite 时，使用现有 `PrototypeSprites.Square` 或 `Circle`。
- 缺失某个敌人皮肤时，仅该类型回退，不影响其他类型。
- 特效资源缺失时跳过该视觉，不影响伤害和状态逻辑。
- 时间环无法初始化时，现有 `SandClockPanel` 数字与沙漏仍正常工作。
- 所有新增视觉对象都不接收输入，不能遮挡棋盘点击和拖放。

## 10. 验证与验收

实施分为三个连续阶段，每个阶段都保持项目可运行：

1. 先完成 `GameSkin` 映射、60 刻度时间环、沙漏/数字、棋盘/战斗背景与沙炉发射器；
2. 再完成 17 种模块图标、8 个精修对象和 4 种敌人主体；
3. 最后完成灼烧、寒冷、融化、携沙、受击和死亡特效，并进行拥挤场景调优。

### 10.1 自动验证

- `GameSkin` 对 17 种 `ModuleType` 和当前 4 种敌人类型都能返回正式 Sprite 或安全回退。
- 时间比例、20 秒警告阈值、扣沙和回沙事件能正确驱动时间环。
- 灼烧、寒冷、融化和携沙状态能正确开启、叠加、清除视觉。
- 视觉组件缺少资源时不抛异常，不改变战斗结果。
- 现有编辑器测试和回归场景继续通过。

### 10.2 视觉验证

- 在 1920×1080 和 1280×720 下检查布局。
- 检查普通、黄潮、坦克混合和 Boss 波的轮廓辨识度。
- 检查火花、雪花、融化、黑洞和爆炸同时出现时仍能辨认目标与炮弹。
- 检查低于 20 秒时主题足够显眼，但棋盘仍可操作。
- 检查 100 个敌人附近的峰值怪潮，确保粒子数量受控且无明显掉帧。

### 10.3 完成标准

- 玩家无需查看文字就能分辨 Swarm、Normal、Tank 和 Boss。
- 玩家无需查看提示就能分辨灼烧、寒冷和携沙状态。
- 17 种模块不再显示为无意义的同类纯色方块。
- 时间刻度环、数字和沙漏共同清楚表达剩余时间，最后 20 秒具有明确压迫感。
- 所有正式美术缺失时，项目仍可用占位图启动并完成战斗。

## 11. 本轮不做

- 不修改数值平衡、波次表、怪物路径、伤害、索敌或附魔规则。
- 不制作逐等级独立模块皮肤。
- 不新增敌人玩法、Boss 技能或新的状态效果。
- 不制作完整角色骨骼动画系统。
- 不重做商店、草稿和结算页面的信息架构；只统一其皮肤资源。
- 不为当前未投入刷怪队列的 `Elite` 制作独立正式皮肤。
