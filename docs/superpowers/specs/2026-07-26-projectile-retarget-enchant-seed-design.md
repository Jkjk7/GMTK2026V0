# 投射物重新索敌与附魔种子稳定化设计

## 背景

雪花和火花模块会在短时间内发射多枚 `ArcSparkProjectile`。多枚弹丸锁定同一敌人时，前几枚可能先将其击杀；当前实现随后把其余弹丸的 `_target` 清空，只让它们减速直飞至寿命结束，导致伤害和状态效果被浪费。

火附魔和惊喜模块当前以“放置格坐标 + 模块类型 + 实例 salt + 等级步进”生成附魔格。模块移动后放置坐标改变，因此附魔格必然改变。此外，实例 salt 只保存在场上组件中，没有进入 `ModuleCardData`；模块拆回手牌再放置时会创建新组件，种子也会丢失。

## 目标

1. 雪花或火花弹丢失首要目标后，自动飞向距离弹丸最近的存活敌人。
2. 同一个附魔模块无论放在棋盘哪个位置，都附魔同一组绝对棋盘格。
3. 附魔模块在移动、拆回手牌、重新放置和升级后保留种子。
4. 保持现有伤害、灼烧、寒冷、融化、弹速、制导强度和弹丸寿命规则不变。
5. 不改变炸弹、黑洞、查理激光和热浪的索敌规则。

## 非目标

- 不实现弹丸伤害预留或防止多枚弹丸同时选择同一目标。
- 不改变塔在发射新弹丸时选择“最左敌人”的现有行为。
- 不为重新索敌增加范围、次数或优先级配置。
- 不改变诅咒格和未解锁格的附魔跳过规则。
- 不重构全部模块数据或全局敌人注册系统。

## 方案选择

### 采用：目标失效时寻找全战场最近敌人

`ArcSparkProjectile` 仅在当前目标为空或死亡时扫描存活敌人，以弹丸当前位置为原点选择距离最近者。选中后继续使用现有制导逻辑；弹丸保留当前速度方向、剩余寿命、来源模块、伤害和命中特效。

该方案不设置额外半径。怪物均位于同一条战斗路线，弹丸自身的 1.6 秒寿命已经限制追踪距离；只有目标失效时才扫描，因此不会在每帧持续增加全场检索成本。

### 未采用：限定重新索敌半径

半径可以限制追踪，但边界外恰好存在敌人时仍会浪费弹丸，并引入需要额外调参的距离常量。

### 未采用：发射时保存备用目标

备用目标也可能在弹丸到达前死亡，并且需要维护目标队列，复杂度高于本次 bug 所需。

## 详细设计

### 投射物数据流

1. 弹丸按现有规则锁定首要目标并发射。
2. 每帧移动前检查 `_target`。
3. 如果目标为空或 `IsAlive == false`，从当前场景敌人中筛选 `IsAlive == true` 的对象。
4. 按敌人与弹丸当前位置的平方距离选择最近者；距离相同时无需额外稳定排序。
5. 找到目标后，立即进入现有制导计算。
6. 没有目标时，保留现有无目标直飞和寿命销毁行为。
7. 命中后仍由 `CombatDamage.Apply` 统一处理伤害、灼烧、寒冷和融化。

重新索敌只发生在目标失效后，不主动从仍存活的首要目标切走，也不会重复命中。

### 附魔模块实例种子

`ModuleCardData` 增加一个非零的附魔实例种子字段。只有 `FireEnchant` 和 `Surprise` 需要该字段；其他模块保持默认值。新附魔卡创建时生成种子，之后所有卡牌转移操作都复制该字段。

同类附魔模块合成升级时，以承载升级结果的目标卡为主，保留目标卡的种子。这样棋盘上或手牌槽中的已有模块继续拥有原附魔布局，升级只按等级步进增加格子。

### 附魔目标生成

`EnchantSeedUtil.BuildTargets` 为兼容现有调用保留放置坐标参数，但不再使用或散列该坐标。每一级目标格仅由以下数据决定：

- 模块类型；
- 模块实例种子；
- 等级步进。

候选格仍从 `GridBoard.Width × GridBoard.Height` 的合法绝对坐标中生成，因此不会产生 7×7 棋盘外坐标。未解锁格和诅咒格继续按现有规则跳过且不补抽。

`Surprise` 的每格附魔类型也只由模块类型、实例种子和目标索引决定，不再依赖模块放置坐标。

### 生命周期

- 棋盘内移动：复用同一组件和 `ModuleCardData`；先清除旧附魔，再以相同种子重建相同格子。
- 拆回手牌：种子随 `ModuleCardData` 返回；场上组件销毁时清除自己仍拥有的附魔。
- 重新放置：新组件读取卡牌中的原种子，重建相同格子。
- 升级：保留目标模块种子，已有等级目标不变，仅增加新等级对应目标。
- 分解：与现有行为相同，销毁组件并清除它仍拥有的附魔。

## 边界与错误处理

- 弹丸重新索敌时忽略 `null`、已死亡或正在销毁的敌人。
- 场上没有存活敌人时不抛异常，弹丸继续直飞并按剩余寿命销毁。
- 新建或旧的默认附魔卡若种子为零，在首次规范化时补生成非零种子，避免默认结构产生完全相同的布局。
- 附魔选择结果只包含棋盘内坐标；当前不可建造或受诅咒的抽取结果继续跳过。
- 保留 `ArcSparkProjectile.cs` 中现有未提交的随机视觉相位改动，不覆盖用户工作。

## 测试与验证

### 自动回归检查

1. 构造两个存活敌人，令弹丸首要目标死亡，验证它改锁距离当前位置最近的第二目标。
2. 验证首要目标仍存活时不会切换。
3. 验证没有存活敌人时不会产生异常，且弹丸最终按寿命销毁。
4. 验证重新索敌后仍携带原伤害和 `Burn` / `Chill` 命中特效。
5. 使用相同模块类型、种子和等级，在不同放置坐标调用目标生成，验证坐标序列完全相同。
6. 验证不同种子可产生不同布局，升级保留旧目标并确定性增加新目标。
7. 验证所有目标均满足 `0 <= col < 7`、`0 <= row < 7`。
8. 验证附魔卡合成后保留目标卡种子。

项目当前没有现成测试程序集，因此实现阶段先建立最小 Unity 回归检查入口；测试先在旧实现上产生预期失败，再写生产修复并验证通过。

### 手动 Play Mode 验收

1. 在右上刷怪密集阶段让雪花或火花短时间对同一怪发射至少三枚弹丸。
2. 前两枚击杀首要目标后，观察剩余弹丸转向其他存活敌人，不再停滞或无效漂浮。
3. 分别移动火附魔和惊喜模块到多个棋盘位置，记录附魔格坐标保持不变。
4. 将附魔模块拆回手牌再放置，确认附魔格和惊喜附魔类型保持不变。
5. 升级附魔模块，确认原附魔格保留，并只增加对应等级的新格。
